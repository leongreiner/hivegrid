# Features in detail

The README lists the features briefly; this is the full description of each.

- Overview dock at the right edge of a tab (`LEADER+o`): every grid pane with its number, state (the hive's states: working, busy, needs you, done, idle, exited, plus shell for a plain shell), time in that state and omp's session title as the row's name (a plain shell shows its directory); while the agent works the second line says what it is running, and when the panes sit in different directories an idle row shows its directory there (a directory every pane shares is left out). A pane inside a git repository also shows its branch at the right end of the second line, in cyan, behind a dot for its working tree (green clean, amber uncommitted changes, red conflicts; committed work is clean) and, in a linked worktree (`git worktree add`), `◇` and the worktree's directory name; a detached HEAD reads `@` and the short commit. The branch is read from the pane's directory (no git process per redraw; the dot costs one `git status` per repository every few seconds) and narrows from the end on a thin dock: the worktree goes first, then the branch is cut, and the line's own text always keeps its room. Panes outside a repository show nothing. Click a row or type its number to jump there (past pane 9 a digit that may start a longer number waits a moment for the next one), or move the selection mark with `j`/`k`, the arrows, `PageUp`/`PageDown` or `g`/`G` and press `Enter` (the mark starts on the active pane, whose number shows in the accent colour; `q`/`Esc` closes the dock), `▦` equalizes the grid and `⊞` arranges it (both only on request). In a narrow dock the title row's buttons drop one by one (`✕ tab` first) before they could touch the title. The `✕` at the right end of the row under the pointer (otherwise of the selected row), or `x`/`Delete` for the selected row, closes that pane: at once when nothing is lost (a shell at its prompt, an exited agent, a done or idle omp, whose session is saved), after a question in the row (`close 2 · working?` with *yes* and *no*; `y` closes, any other key or click keeps it) when work would be interrupted (working, busy, needs you, a bell, or a program other than the shell in the foreground). `✕ tab` in the title row, or `X`, closes the whole tab, the bar and the dock with it, after one question that counts the agents at work (`close 6 panes · 1 needs you, 2 working?`). The other panes stay where they are; after `x` the keys stay in the dock with the mark on the next row, after a click they go to the grid pane used last (the closed pane's neighbour if it was that one); closing the last grid pane closes the tab. Rows that do not fit scroll with the wheel; otherwise the list follows the selection. When the panes no longer fit with a blank line between them, every second row is shaded so rows stay apart (the git view does the same). The dock runs from the header to the bottom edge. It opens at 18% of the window, 30 to 48 columns; a width you drag it to is remembered and scales with the window. On the Hivegrid build an open dock follows window resizes, and opening or closing panes never changes its width. A pane picker (`LEADER+g`) lists every agent too, and background panes raise bell toasts. omp panes report their state exactly, through the run-state glyph omp puts in the terminal title. With room (a third line per row), each agent row also shows the tokens and cost omp reported (`1.3M tok · $4.82`, `~$4.82` when omp estimated the cost from list prices rather than a provider's charge, a dim `—` when nothing was reported) and the title row gets a total of the rows; the Agents panel has the same columns and a total for the window. Local CPU and RAM are never part of it.
- Nothing re-tiles the grid by itself: a split, a closed pane, a window resize, the sidebar view or the dock opening or closing leave every pane where it is (a new pane sits exactly where its split put it; a window resize keeps the proportions on the Hivegrid build). Arranging happens only when you ask: `Ctrl+Shift+A` or the `⊞` button of the dock re-tiles the panes into the grid that reads best for their number and the window's shape (five panes side by side become 3 + 2 in two rows; panes are moved, never recreated, and keep their numbers), and `LEADER+e`, `Ctrl+Shift+E` or `▦` evens out the dividers.
- `omp-grid` launcher: equal grids, main-plus-side and column layouts, per-pane directories, optional new tab.
- Resize, pane and broadcast key tables, and an equalize command that evens out all dividers: every split gives its panes equal shares (a column of three beside a column of two: equal columns, equal rows within each). Rotate and swap move only the grid panes, keeping the layout's geometry; the sidebar and the dock never move.
- Broadcast mode that types into every pane of the tab, with a red `BROADCAST` pill in the header; the resize, pane and account-launch modes show an amber `RESIZE`, `PANE` or `ACCOUNT` pill there while they are active, followed by the mode's keys while there is room, and a `ZOOM` pill shows while the tab has a zoomed pane (a click on it unzooms on the Hivegrid build). The pills stay at any window width; the narrowest header keeps the context pill and the CPU chip.
- One themed Hivegrid picker for every list to choose from (`LEADER+g`, `Alt+q`, the `+` menu, pane mode `g`/`s`/`S`) and for the account-switch question (No is the default): type to filter (or `/` first), `j`/`k` or the arrows move, a digit picks, `Enter` chooses, `Esc` clears the filter then closes, and the mouse hovers, clicks and scrolls. On stock WezTerm the same lists open in WezTerm's own selector.
- The header is a hierarchy. Left to right on the right side: the **context** pill (bright, bold project name: the repository of the active pane, else its directory; the workspace before it when it is not `default`; the git branch; then the agents that want a look, `? 1 needs you  ↻ 2 working  ◔ 1 busy`, in the dock's glyphs and colours; a click on the counts opens the pane picker), then the Claude usage and the system stats as quiet text on the header band: dim labels, muted numbers, a colour only past a threshold (amber from 60 % for the system, 50 % for the quota; red above 85 % and from 80 %), so only green, amber and red carry meaning and the accent stays for selection. The pills for the key modes stay as they were. As the window narrows the quota bars and the system amounts go first, then the workspace and branch, then the quota, and last the project's name is shortened; the CPU chip and the agent counts always stay.
- System stats in the header: one calm summary, `CPU  12%  RAM  48%  GPU  37%`, in muted text. A metric past 60 % turns amber, above 85 % red and then shows its amount (`29.0G/32G`); the disk (`DSK  95% 48G free`) appears only once it is 60 % full. A click opens the system monitor for the detail and history; `Alt+s` hides the group.
- Claude Code usage (5h and 7d windows) for every account in the header as muted numbers with slim bars (amber from 50 %, red from 80 %, then with the reset countdown; an account that needs a login shows only an amber `login` chip); accounts are discovered, so a new one appears on its own. The account whose omp runs in the pane you are working in is bold and raised, the header's one selection, and the highlight follows focus from pane to pane within a second (nothing is highlighted in a pane without omp). Clicking an account starts omp with it, or moves the omp already running in that pane to it with the same chat.
- Panels inside the window (the gear button of the left bar, `LEADER+,`, `+` menu): settings (themes, key bindings, accounts), usage history charts, agent overview and a system monitor.
- Web pane (the Hivegrid WezTerm build and a Chromium-family browser: Google Chrome, Chromium, Brave, Edge or Vivaldi): a page in a pane of the grid, next to the agents. `LEADER+w`, then `n` asks for a URL (or search words; Enter alone opens the home page) and opens it beside the last grid pane; the globe button of the left bar does the same when the tab has no web pane, and focuses the tab's web pane when it has one (it appears when a browser is found, and not on a bar under 17 rows tall); clicking an `http(s)` link in a terminal pane opens it in the tab's web pane (Settings, Web: or leave links to the system browser). The page is a pane like any other: it is numbered, split, zoomed (`Alt+z`), arranged, rotated and swapped with the terminals, it shows in the overview dock and the pickers as `◍ web` with its host and page title, and broadcast never types into it. Mouse, wheel, keys and paste go to the page; Hivegrid's own keys (`Alt+h/j/k/l`, the leader, `Ctrl+V`) win. `wezterm cli split-pane --url URL [--profile NAME] [--private] [--browser PATH]` and `+ web` in the agent hive open one from a script or the hive. Each profile name is one headless browser process (cookies and logins in `~/.local/share/hivegrid/web/profile-<name>`; a private pane forgets them when it closes).
- Permanent narrow bar at the left of every tab with buttons for the file explorer, the git view, the overview dock and the settings panel. The explorer is a yazi sidebar; the git view lists every repository of the working directory (like VS Code's Source Control repositories) with branch, ahead/behind, change counts and a merge, rebase, cherry-pick, revert or bisect in progress, and opens lazygit (in Hivegrid colours; a theme in your own lazygit config wins) in the one you pick. A coloured dot gives the working-tree state (green clean, amber changes, red conflicts), the title line the scanned directory and how many repositories are in each state, and repositories with GitHub Actions workflows show a `✓` / `✗` right after the dot for the latest runs on the checked-out branch, a spinning amber `⠋` while one is unfinished (read through `gh` every 2 minutes for the rows in view, every 10 minutes for the others and every 15 s while a run is unfinished, which keeps a workspace of a hundred repositories at about a fifth of GitHub's hourly API limit; `–` when the branch has no runs or only cancelled or skipped ones, `?` when `gh` cannot tell, nothing without workflows). It follows the active pane: focusing a pane in another directory (or a `cd` there) restarts it in that directory. `Ctrl+F` / `Ctrl+G` do the same as the buttons.
- Hover feedback on the bar, the overview dock and the git view: the pointer turns into a hand over the bar's buttons and the git view's rows, and a hovered button (or dock or git view row, or `⊞` / `▦`) fades to a lighter shade in about 150 ms and back in about 200 ms (only while it fades does anything redraw). The hover also ends when the pointer leaves the bar, dock or git view by any route, because the Hivegrid build tells the program ([the WezTerm build](wezterm-build.md)). Stock WezTerm sends no hover to a pane that has no focus, so there the bar and dock stay plain.
- Smart `Ctrl+C` (copy with a selection, interrupt otherwise), `Ctrl+V` paste, `Shift+Arrow` splits, `Alt+Arrow` focus; `Ctrl+Arrow` and `Ctrl+Backspace` reach the shell (word jump, delete word).
- Dark-blue theme with rounded tabs level with the header pills, the app icon's honeycomb of seven hexagons drawn at the left of the header (click it to open the agent hive), wide padding, and dimmed inactive panes.
