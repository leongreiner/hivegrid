# Notes and limits

- Agent state is shown in the overview dock, the pane picker and bell toasts; the header only counts the agents that work, are busy or need you (all tabs of the window), and the tab titles show none. A background tab's own state is only visible after switching to it. On stock WezTerm the header is not clickable.
- The overlay covers the whole active tab; there is no centred modal mode.
- Moving an omp chat to another account needs omp's per-terminal session record (omp 18); with several omp processes in one terminal it refuses rather than guess. The busy check uses the same heuristic as the agent states.
- omp's state comes from the run-state glyph in its terminal title (`tui.titleState`, on by default in omp); when that is off, and for other agents, detection is heuristic: it combines the foreground process, screen text markers, the bell and screen activity.
- The sidebar bar spans the full window height on the Hivegrid build (a top-level split); on stock WezTerm 20240203, which mis-sizes top-level splits, it and the overview dock sit beside the leftmost / top-right pane only. On the Hivegrid build the explorer and git view form a full-height column right of the bar, and the grid shrinks as a whole (an even grid stays even); switching the view, or the git view following another directory, keeps the column in place and the grid still. The view is 22% of the window (28 to 60 columns) and follows window resizes until you drag its divider: that width, scaled with the window, then stays for the tab and is taken by tabs without their own. The git view never restarts while lazygit runs in it; it follows the grid once lazygit quits. On stock WezTerm the view is docked beside the leftmost pane.
- The sidebar views start in the working directory of the pane they were opened from (the git view scans it for repositories: the one around it and those below it, `HIVEGRID_GIT_DEPTH` levels deep, default 3; with a single repository it opens lazygit there directly, with none it says so). A pane whose shell reports a path from another host, such as an ssh session, uses the directory of its local foreground process instead.
- The explorer copies paths with the terminal clipboard escape (OSC 52), which WezTerm accepts, and also through `wl-copy`, `xclip` or `xsel` when present.
- `Ctrl+V` paste is not fanned out in broadcast mode, because the clipboard is not readable from Lua.
- Web panes need the Hivegrid WezTerm build and a Chromium-family browser (`install.sh` warns when none is found; Settings, Web chooses one, `HIVEGRID_CHROME` overrides the choice; the left bar's browser button shows only when one is found). The choice is read when a browser process starts: one browser serves every pane of a profile, so a new choice applies once the last web pane of that profile has closed. The header row of the pane (back, forward, reload, the address and search field, collapse) is drawn by the Hivegrid build: `LEADER+w h` shows or hides it, `LEADER+w l` types in it (it shows just for the edit when hidden); a location that is no URL is searched with the engine of Settings, Web (Google by default). `Ctrl+L` in the page does the same as `l`. The collapse button (`▴`) hides the row; the way back is `LEADER+w h`, `l` or `Ctrl+L`, since a collapsed row leaves nothing to click. The state belongs to the pane and is not kept by the session restore (a restored pane shows its header), and a pane under 3 rows tall has none. Mouse wheel scrolling moves a notch at a time (the compositor reports wheel steps); IME text is committed to the page but the candidate window sits at the pane's top-left corner; drag and drop is not forwarded; a page's downloads, permission prompts and JS dialogs are answered by Hivegrid (refused or dismissed), and pages do not survive a restart of Hivegrid (cookies and logins of a profile do). They work in the local domain only, not through a mux server, an SSH domain or a mux client.
- A web pane is never part of broadcast (starting broadcast from one is refused, and focusing one while it runs ends it, so typing into a page never reaches the other panes); in a layout it counts like a terminal pane, so arrange (`Ctrl+Shift+A`) tiles around it. The overview dock lets it close without asking (state `web`).
- Web profiles keep cookies and logins on disk in your data directory (`~/.local/share/hivegrid/web/profile-<name>`, mode 0700) with Chrome's basic password store, so they are not encrypted by the OS keyring: anything running as your user can read them; use a private web pane (ephemeral profile) for sessions you do not want kept.
- Web panes launch Chrome or Chromium, and without one the web key table says `Chrome or Chromium not found` and link clicks stay with the system browser; Snap and Flatpak browsers are not offered: the snap cannot write the hidden profile directory under your home and its launcher does not reliably pass on the DevTools pipe, so install Google Chrome or a non-snap Chromium (or point Settings, Web, or `HIVEGRID_CHROME`, at one). Firefox has no screencast API and cannot be used.
- `HIVEGRID_WEB_DEVTOOLS=1` is a debug option: it makes the browser listen on an unauthenticated DevTools port on localhost, which any local process can use to control the browser and read its cookies, so leave it unset.
